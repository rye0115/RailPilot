# 05 · 合规、许可证与风险

> 不是法律意见。以下是 2026-11-14 前的公开监管口径与判例，用于产品边界设计；具体个案请咨询律师。

## 1. 结论

| 使用方式 | 风险等级 | 判断 |
|---|---|---|
| 只用官方 App 的预填/提醒/候补/预约 | 低 | 推荐 |
| 个人自用、单账号、低频、真实浏览器、人工支付 | 中 | 灰色；可能违反平台协议/触发风控，但通常不等于犯罪 |
| 高频 API、多账号、代理池、验证码绕过 | 高 | 明确违反平台规则/监管口径；可能被锁号、行政处罚 |
| 收费代抢、批量囤票、倒卖 | 极高 | 已有实刑判例；可能构成非法获取计算机信息系统数据罪、倒卖车票罪等 |
| 复制没有 LICENSE 的代码并分发 | 高 | 著作权侵权；与“抢票”本身无关，但会放大整体风险 |

**一句话**：技术本身不是护身符；**规模、盈利、绕过安全措施**是定性时最危险的三件事。个人自用也要把这三件事压到最低。

## 3. 可能涉及的法律

| 法律/条款 | 风险点 | 与本案的关系 |
|---|---|---|
| 《刑法》第 285 条 | 非法获取计算机信息系统数据；提供侵入、非法控制计算机信息系统的程序/工具 | 绕过验证码、伪造设备、批量账号、高频请求可能被认定“侵入/非法获取” |
| 《刑法》第 227 条 | 倒卖车票、船票罪 | 加价代抢、囤票转卖 |
| 《网络安全法》 | 不得危害关键信息基础设施安全 | 12306 属于关键信息基础设施；高频/大规模访问可能被认定危害 |
| 《关键信息基础设施安全保护条例》 | 运营者/个人的安全义务 | 监管约谈 7 家平台的依据 |
| 《个人信息保护法》 | 收集、存储、使用乘车人信息 | 代抢收集身份证/手机号；本地工具也要最小化 |
| 《反不正当竞争法》/《消费者权益保护法》 | 虚假宣传“加速/优先” | 平台“加速包”被处罚的依据 |
| 《铁路安全管理条例》 | 买短乘长导致超员 | 监管点名“买短乘长”有安全风险 |

## 4. 平台协议与许可证

### 4.1 12306 服务协议

- 12306 是唯一官方网络售票渠道，从未与第三方合作。
- 平台协议通常禁止以机器人、爬虫等非认可方式访问/干扰系统（公开技术文章多引用为第 6.3 条；以官网现行文本为准）。
- 即使个人自用，自动化访问仍可能违反协议，导致：
  - 登录被拒/验证码；
  - 订单进慢速队列/拒绝出票；
  - 账号当天锁购票（3 次取消）；
  - 严重时账号被限制。

### 4.2 开源许可证

| 许可证 | 义务 | 对我们的约束 |
|---|---|---|
| MIT | 保留版权/许可声明 | 可 fork/修改/再发布；保留 `LICENSE` |
| Apache-2.0 | 保留 LICENSE/NOTICE；专利授权 | 可复用；不要用作者商标 |
| 未声明 | 默认“保留所有权利” | **不能复制/fork/再发布**；只能读思路/提 PR |
| 闭源（Bypass） | 只可用官方发布版 | 不能反编译/复制/二次分发 |
| Qt/PySide6 | LGPL/GPL | 分发 PySide6 应用需遵守 LGPL/GPL（动态链接、替换库、许可证文本） |
| Chromium/Electron | BSD 等 | 保留版权/许可证；注意 Electron 打包条款 |

**本项目策略**：
- **只参考算法/流程，不复制代码**；代码自己写；
- 如确实需要复制 MIT/Apache 代码，单独 commit、保留 LICENSE/NOTICE、在 `docs/07` 记录；
- 未声明项目（如 12306FairTicket）只读，不复制、不 fork；
- 自研代码默认私有；如未来开源，建议 MIT，并用 `NOTICE` 列清楚“参考”与“复制”的区别；
- 不把 Bypass 的图标/文案/代码放进仓库。

> 数据安全审计（明文 Cookie、反检测、第三方 IP 查询、许可证）见 [`08-security-audit.md`](08-security-audit.md)。

## 6. 红线（写进代码/文档）

1. **不收费、不代抢、不转卖**；只服务本人/已授权同行人。
2. **单账号**；不提供账号池、多账号切换、批量注册。
3. **不绕过验证码/滑块/设备指纹**；遇到验证码就人工。
4. **不做代理池/IP 轮换**；不伪造终端。
5. **不高频**：查询 ≥5 秒，售罄后 ≥30 秒；T0 冲刺 ≤3 秒。
6. **不自动支付**（默认）；自动支付必须显式授权 + 限额。
7. **不买短乘长/不默认买长乘短**；只提示风险。
8. **不复制未授权代码**；保留 LICENSE/NOTICE。
9. **不公开分享乘客信息/订单截图**；日志脱敏。
10. **不把工具包装成“官方合作/优先通道”**。

## 7. 隐私设计

- 登录：扫码，不收密码；Cookie 存 OS keyring/DPAPI，退出即删。
- 乘车人：只存姓名/类型；身份证/手机号留在 12306 账号里，不落本地库。
- 日志：订单号可保留；身份证/手机号/地址打码；截图裁剪到订单区域。
- 通知：只发“订单已锁/支付截止”，不发完整身份证/票号。
- 遥测：默认关闭；不上传任何数据。
- 保留期：日志 30 天，截图 7 天；可一键清空。

- [ ] 顶层 `LICENSE`（MIT/Apache）和 `NOTICE`；

- [ ] 不提供“加速/成功率”营销；
- [ ] 不包含验证码模型/代理列表/账号池；
- [ ] 发布前做一次许可证扫描（如 `pip-licenses`/`license-checker`）。

## 9. 建议

- 如果只是自己回家买票：**先用官方候补/预填**；本工具只作为“提醒 + 候补组合 + 支付倒计时”的辅助。
- 如果要做工具：**个人自用、单账号、低频、人工支付、不收费**；把“规模/盈利/绕过”三个风险因子压到最低。
- 如果要公开：先补许可证/NOTICE，做合规审查；不要把它包装成“抢票神器”。
- 如果线路在京沪试点：优先用官方预约购票，比任何脚本都稳。
