# 06 · 路线图：2 天安全 spike + 4 周 MVP

> 前提：**参考算法，自研代码；安全门槛先过，功能后做。**
> 不在空地上盖房，也不把别人的代码搬进来。
>
> 2026-11-14 更新：v0.1 安全内核 + 查询/候补/护栏已落地；真实下单仍未启用，先做现场登录/订单回读再开 `--live`。

## 0. 总览

```text
Day 0–2   安全 spike（DPAPI/临时上下文/白名单/脱敏） → go / no-go
Week 1    骨架：配置/状态/事件/时钟/候选
Week 2    官方页面适配：查询/预填/提交/回读/幂等
Week 3    候补/护栏/通知/UI + 本地 mock 测试
Week 4    现场测试 + 安全复测 + 打包 + 文档
```

## 1. Day 0–2：安全 spike（先别写 UI）

| 任务 | 产出 | 通过标准 |
|---|---|---|
| DPAPI 加解密 | `security/dpapi.py` + 单元测试 | 当前用户可解密；另一个 Windows 用户解密失败 |
| 临时浏览器上下文 | Playwright 打开官方查询页 | 退出后无 `storage_state`/profile 文件；`strings` 无 `tk=` |
| 网络白名单 | `context.route` 拦截 | 只允许 `*.12306.cn`；其他请求 abort 并记录 |
| 日志脱敏 | `security/redact.py` | 合成身份证/手机号/Cookie 输出已打码 |
| 静态扫描 | `bandit`/`pip-audit`/`gitleaks` | 无 high/critical；无硬编码密钥 |
| 决策 | go/no-go 记录 | 见下方门槛 |

**Go 门槛**：
- DPAPI 用户绑定成立；
- 临时上下文退出后无 Cookie 文件；
- 白名单能挡住非 12306 请求；
- 脱敏测试通过；
- 依赖扫描无 high。

**No-go 处理**：
- 如果 Playwright 无法在不落盘的情况下稳定登录/提交，退回“官方助手”定位：只做预填检查 + 候补计划 + 通知，不做自动提交。
- 如果 DPAPI/白名单实现成本过高，先做“只读监控 + 通知”，不碰下单。

## 2. Week 1：骨架

| 天 | 任务 | 产出 |
|---|---|---|
| D1 | PySide6 窗口壳 + 任务列表/候选表 | 能启动/保存任务（DPAPI state） |
| D2 | 配置（Pydantic/YAML）+ 日志（脱敏） | `config.yaml` + 日志 |
| D3 | `events.db` + 事件分类 | 时间线可查 |
| D4 | `clock.py` 校时 + 倒计时 | 偏移稳定 ≤1s（HTTP Date 秒级）；单调 |
| D5 | `planner.py` 起售时间/候选排序 | 10 个车站校验 |

**验收**：
- 状态文件是 DPAPI 密文；`strings` 无姓名/证件号；
- 日志无 PII；
- 时钟单元测试通过。

## 3. Week 2：官方页面适配 + 幂等

| 天 | 任务 | 产出 |
|---|---|---|
| D1 | `rail/adapter.py` 查询 + 选择器集中 | 查到指定日期/区间 |
| D2 | 预填检查/打开官方预填页 | 缺项报告 |
| D3 | T0 提交（只点一次）+ 结果解析 | 空跑到“确认订单”前 |
| D4 | `read_orders()` + 幂等键 + 未支付订单检查 | 100 次空跑 0 重复 |
| D5 | `guard.py` 支付倒计时/取消预算 | 第 2 次取消硬停 |

**验收**：
- T0 首提交 p95 ≤500ms；
- 未知响应 2 秒内回读；
- 未支付订单只允许 1 个；
- 取消预算 0 违规。

## 4. Week 3：候补 + 通知 + UI

| 天 | 任务 | 产出 |
|---|---|---|
| D1–D2 | `waitlist.py` 展开/过滤/拆分/导出 | 6 单 × 3 日期 × 60 组合边界测试 |
| D3 | `notify/channels.py` 桌面 + 1 个 webhook | 本地 <2 秒；只发状态/截止 |
| D4 | 作战面板/候补面板 | 不重写主界面 |
| D5 | 本地 mock 页面 + 故障注入 | 排队/售罄/302/验证码/超时 |

**验收**：
- 候补计划 2 秒内生成；
- 每单 ≥40 有效组合；
- 通知不含姓名/证件号；
- mock 故障全部有明确状态。

## 5. Week 4：现场 + 安全复测 + 打包

| 天 | 任务 | 产出 |
|---|---|---|
| D1 | 低峰线路现场测试（只买 1 张可退票，人工支付；注意 3 次取消限制） | 测试记录/脱敏截图 |
| D2 | 修复选择器/时序/通知/异常 | 回归测试 |
| D3 | 安全复测：`strings`/mitmproxy/DPAPI/日志 | 安全报告 |
| D4 | PyInstaller 打包 + 安装/卸载 | `dist/` + SHA256 |
| D5 | 文档/复盘 + go/no-go for v0.2 | 复盘记录 |

**验收**：
- 真实跑通一次“查询 → 提交 → 锁座 → 支付”（可退票线路）；
- 数据目录无明文 Cookie/证件号；
- 只访问 `*.12306.cn`；
- 包在新机器 10 分钟内跑起来；
- 文档覆盖“怎么用/怎么退/怎么报错”。

## 7. 验收门槛（Go/No-Go）

| 门槛 | 目标 | 不达标怎么办 |
|---|---|---|
| DPAPI 用户绑定 | 另一用户解不开 | 不做持久化，只内存会话 |
| 无明文 Cookie | `strings` 无 `tk=` | 修存储层；不过不发版 |
| 无 PII 落盘 | 无 18 位身份证/11 位手机号 | 修数据模型；不过不发版 |
| 网络白名单 | 只看到 `*.12306.cn` | 修拦截；不过不发版 |
| 日志脱敏 | 合成 PII 已打码 | 修 formatter |
| T0 延迟 | p95 ≤500ms | 优化/降级为“官方助手” |
| 重复订单 | 0/100 空跑 | 加幂等/回读 |
| 取消预算 | 0 违规 | 硬停逻辑 |
| 候补计划 | 2 秒内、≥40 组合 | 优化算法 |
| 现场跑通 | 1 次锁座+支付 | 修选择器/时序 |
| 依赖漏洞 | 无 high/critical | 升级/替换 |
| 静态扫描 | 无 high | 修代码 |

## 8. 指标

| 指标 | 目标 |

## 9. 风险与应对

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| Playwright 临时上下文登录不稳 | 中 | 高 | 测试系统 Edge/自带 Chromium；必要时 DPAPI 加密恢复 |
| 页面改版 | 高 | 中 | 选择器集中；每日冒烟；快速回滚 |
| 风控/锁号 | 中 | 高 | 低频、单账号、停止条件；官方候补兜底 |
| 同用户恶意软件 | 中 | 高 | 全盘加密/EDR/最小软件面；DPAPI 不是万能的 |
| 重复订单 | 中 | 高 | 幂等 + 回读 + 未支付检查 |
| 现场测试失败 | 中 | 中 | 低峰线路、可退票、人工支付；失败退回“官方助手” |
| 依赖供应链 | 中 | 中 | 锁版本+哈希；不自动下载；`pip-audit` |

## 10. 开放问题

1. GUI 用 PySide6 还是 Tauri？→ 优先 PySide6，少一个 Chromium/Node 攻击面。
2. 会话默认内存还是 DPAPI 恢复？→ 默认内存；DPAPI 作为可选“记住登录”。
3. 候补默认自动提交还是只生成计划？→ 默认只生成/打开页面，P1 再考虑自动提交。
4. 是否支持京沪预约？→ 若你的线路在试点范围，P1 必做。
5. 自动支付做不做？→ 只有前三阶段稳定、安全复测全过、能接受资金风险才做。
6. 是否公开分发？→ 个人自用优先；公开分发前做许可证/合规/代码签名审查。
