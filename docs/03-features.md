# 03 · 功能清单（自研，参考算法）

> 定位：**参考他们的算法/流程，自研一个安全、最小、可审计的客户端。** 不 fork、不复制代码。
> 安全底线：见 `docs/08-security-audit.md` 的 S-01 ~ S-12；不过安全门槛，不进入功能开发。

## 1. 先盘点：哪些“重活”只参考，不重造

| 能力 | 参考来源 | 自研策略 |
|---|---|---|
| 官方页面查询/余票 | c66-m、12306FairTicket | 自己实现页面适配；低频、低频、再低频 |
| 真实浏览器提交 | c66-m | 用 Playwright 自带 Chromium/系统 Edge；不注入反检测 |
| 订单回读 + 时间戳归因 | c66-m | 按思路自己写；只读官方订单页/接口 |
| 扫码登录/本地会话 | 12306-helper | 自己实现；Cookie 默认内存 |
| 校时/预热/购物车 | 12306FairTicket、TopF1ag | 按算法自己实现；不复制代码 |
| 通知适配器 | py12306、RailWatch | 按接口自己写；默认只发状态/截止 |
| 候补/支付/取消规则 | 12306 官方 | 直接按公开规则实现 |

**结论**：工作量集中在“页面适配 + 时序 + 幂等 + 安全”，不是“从零发明抢票”。

## 2. 设计原则

1. **官方优先**：能用预填/提醒/候补/预约解决的，不自己造。
2. **单账号、本人**：不提供多账号、代抢、账号池。
3. **数据不出本机**：默认不落盘；必须落盘时 DPAPI + ACL。
4. **低频、可解释**：每个请求都有理由；每个失败都有状态。
5. **人工支付**：默认只打开支付页；自动支付必须显式授权 + 限额。
6. **最小实现**：先做 6 个模块，代码量控制在 2,500 行以内（不含第三方库）。

| ID | 功能 | 参考来源 | 说明 | 验收标准 |
|---|---|---|---|---|
| F-01 | 起售日历 | 官方 App、Bypass | 按出发站 + 日期查起售时间；缓存 24h；过期提醒 | 10 个车站与官方页面一致；过期 >24h 提示刷新 |

| F-14 | 安全自检 | 08 审计 | `strings`/网络/DPAPI/日志脱敏自检 | 10 项全过才发版 |

## 6. 反功能（明确不做）

| 反功能 | 为什么不做 | 替代方案 |
|---|---|---|
| 验证码识别/滑块绕过 | 违规；判例中的关键情节；模型维护无底洞 | 扫码登录、人工验证 |
| 多账号/账号池 | 违反实名制和平台规则；风控重点；可能涉刑 | 单账号、本人乘车 |
| 代理池/IP 轮换 | 规避风控；监管明确禁止干扰安全核验 | 家庭网络、低频 |
| 高频轮询（<1 秒） | 进慢速队列、拒绝出票、封 IP | 查询 ≥5 秒；售罄转候补 |
| CDN IP 扫描 | 数据不可信，容易被识别 | 官方域名 |
| 反检测/指纹伪造 | 与“不绕过风控”冲突 | 真实浏览器、人工登录 |
| 自动支付默认开 | 误买/重复买/退款麻烦 | 人工支付；P2 显式授权 |
| “加速包/成功率” | 虚假宣传；监管点名 | 只展示可解释状态 |
| 买短乘长/买长乘短 | 监管点名；超员安全风险；合同风险 | 只提示风险，不自动下单 |
| 代抢收费/倒卖 | 可能构成倒卖车票罪/非法获取数据罪 | 个人自用，不收费 |
| 明文 Cookie/密码 | 泄露即账号被盗 | DPAPI/内存会话 |

## 7. 关键流程

### 7.1 开售前 24 小时

1. 输入出发站、到达站、日期；查起售时间并写入任务。
2. 选择车次/席别/乘车人，拖拽优先级。
3. 检查：登录态、乘车人核验、学生资质、预填、支付方式。
4. 校时；生成“预检清单”，缺项标红。

### 7.2 开售前 10 分钟

1. 自动复校；打开官方页面并预热。
2. T-2 分钟停止所有非必要请求（“临战静默”）。
3. T-10 秒再次校时，锁定倒计时。
4. 显示“只差一次点击”的状态。

### 7.3 T0 提交

1. T0 + 50–150ms 点提交。
2. 若返回排队：等待，不重复提交；显示排队状态。
3. 若成功：立即停止同任务其他候选；进入支付倒计时。
4. 若售罄：停止重试，进入候补流程。
5. 若验证码/登录失效/风控：停止，提示人工处理，冷却 10 分钟。

### 7.4 售罄转候补

1. 按用户可接受的日期/时段/席别生成组合。
2. 优先“直达 + 时间合适 + 席别可接受”；过滤换乘 <30 分钟、到达太晚等。
3. 拆成 ≤6 个订单；每单 ≤3 日期、≤60 组合、≤19 人。
4. 勾选“接受新增列车”；设置截止时间（默认开车前 2 小时，而不是 20 分钟）。
5. 用户确认后提交；提醒预付款 30 分钟内完成。
6. 提交后停止刷票，只跟踪兑现状态。

### 7.5 锁座后

1. 显示订单号、席位、金额、支付截止倒计时。
2. 桌面通知 + 手机推送；一键打开支付页。
3. 支付成功：归档任务；提示退改签规则。
4. 未支付超时：标记失败，提示“席位已释放”，不要自动再抢同一单。

## 9. 成功指标

| 指标 | 目标 | 说明 |
|---|---|---|
| 预填完成率 | ≥95% | 任务启动前完成预填的任务占比 |
| T0 首提交延迟 | p95 ≤500ms | 从起售时刻到第一个提交请求 |
| 锁座率 | 按线路统计，不承诺 | 有票场景下成功拿到未支付订单的比例 |
| 支付及时率 | ≥98% | 锁座后在截止前完成支付 |
| 候补组合数 | 每单 ≥40 个有效组合 | 不是凑数，需通过可行性过滤 |
| 重复订单 | 0 | 100 次空跑 + 真实场景 |
| 取消预算违规 | 0 | 一天不超过 2 次手动取消 |
| 明文 Cookie/证件号 | 0 | `strings`/磁盘扫描 |
| 非 12306 外联 | 0 | mitmproxy/Wireshark |
| 用户手动操作次数 | ≤5 次 | 开售前到支付完成 |

## 10. 版本范围建议

- **v0.1（4 周 MVP）**：F-01 ~ F-14，Windows 单平台，单账号，单任务为主，人工支付。
- **v0.2**：F-15 ~ F-19，多任务、中转、选座/选铺、京沪预约、自动打开支付页。
- **v0.3**：F-20 ~ F-21，历史、停运守卫。
- **v1.0**：只有前三阶段稳定、无锁号、无重复订单、安全自检全过，才考虑 F-22 自动支付。

> 先做“安全 + 主链”，再做“功能全”。不要一上来重写 GUI 或下单引擎。
